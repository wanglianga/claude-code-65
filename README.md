# 城市社区法律援助预约与案件分流平台

## 原始需求

> 建设城市社区法律援助预约与案件分流平台，可使用 Next.js、NestJS 和 PostgreSQL。居民提交劳动纠纷、婚姻家事、房屋租赁、邻里侵权、消费维权或行政复议咨询时，平台记录诉求、证据材料、时间节点、家庭收入、是否残障、是否涉未成年人和紧急程度。社区工作人员先做资格初审，判断是否属于法律援助、人民调解、司法所转介、热线解答或商业律师服务。律师接案前，需要看到案件事实、关键期限、证据完整度、冲突主体和是否存在利益冲突。若居民材料不全、对方已经起诉、诉讼时效临近、家庭暴力风险、老人不会线上上传或律师临时请假，平台要把居民、社区工作人员、值班律师、司法所和志愿者放在同一服务单里推进。服务结束后，咨询意见、材料补正、转介去向、律师工时、回访结果和居民满意度进入档案，用于评估社区法律援助资源配置。平台还要支持社区活动现场咨询、热线转入、线下纸质材料补录和跨街道转介。对涉及欠薪群体、家庭暴力、老人赡养和未成年人权益的案件，要有更细的保密、优先级和协同单位规则。

## 项目简介

面向城市社区的公共法律服务一站式平台，覆盖 **咨询提交 → 资格初审 → 案件分流 → 律师接案 → 多角色服务单协同 → 结案归档 → 资源配置评估** 全流程。

- **六类咨询**：劳动纠纷、婚姻家事、房屋租赁、邻里侵权、消费维权、行政复议
- **五类分流**：法律援助、人民调解、司法所转介、热线解答、商业律师服务
- **四种登记渠道**：社区活动现场、热线转入、线下纸质材料补录、跨街道转介（+居民线上提交）
- **特殊规则引擎**：欠薪群体 / 家庭暴力 / 老人赡养 / 未成年人权益案件自动提升优先级、加强保密级别、生成协同单位任务
- **期限风险预警**：按事件日期推算法定时效（劳动仲裁 1 年 / 租赁诉讼 3 年），结合证据完整度与办理节点评估风险；高风险案件置顶工作人员首页；支持一键生成材料清单、登记居民意愿与期限提醒（自动评估提醒及时性，用于服务质量复盘）
- **同一服务单**：居民、社区工作人员、值班律师、司法所、志愿者在同一服务单中通过协同任务推进

## 技术架构

```
┌────────────┐   浏览器    ┌─────────────────┐   内网反向代理 /api/*   ┌─────────────────┐        ┌──────────────┐
│   用户浏览器 │ ────────▶ │  web (Next.js)  │ ────────────────────▶ │  api (NestJS)   │ ──────▶ │ db (Postgres)│
└────────────┘           │  :3000（对外发布） │                       │  :4000（不对外） │        │  :5432(不对外)│
                         └─────────────────┘                       └─────────────────┘        └──────────────┘
```

| 服务 | 技术 | 说明 |
| --- | --- | --- |
| web | Next.js 14（App Router, standalone 输出） | 前端页面 + `/api/*` 反向代理，唯一对外发布端口 |
| api | NestJS 10 + Prisma 5 | REST API、JWT 角色鉴权、特殊规则引擎、文件上传 |
| db | PostgreSQL 16 | 数据持久化（命名卷 pgdata） |

- 仅 `web` 服务发布到宿主端口（`${CC_PUBLISH_PORT}:3000`），`api`、`db` 仅在 compose 内部网络互访
- 上传的证据材料保存在 `uploads` 命名卷
- 数据库 / 缓存等依赖服务不发布宿主端口

## 一键启动（Docker）

前置条件：Docker + Docker Compose v2。

```bash
cp .env.example .env        # 可选：修改端口/密码；评审环境已注入 CC_PUBLISH_PORT
docker compose up -d --build
```

启动后：

- `api` 容器启动时自动执行 `prisma db push`（建表）+ `prisma/seed.js`（幂等演示数据）
- 查看实际发布端口：`docker compose port web 3000`
- 浏览器访问：`http://localhost:<端口>`（容器内验证可用 `http://host.docker.internal:<端口>`）
- 健康检查：`docker compose ps`（web/api 均带 HEALTHCHECK）

停止并释放资源：

```bash
docker compose down            # 保留数据卷
docker compose down -v         # 连数据一起清空
```

## 关键业务流程（验证路径）

1. **居民提交**：`resident01` 登录 → 提交咨询 → 填写诉求/收入/特殊情形/时间节点 → 详情页上传证据材料
2. **资格初审分流**：`staff01` 登录 → 案件分流 → 打开待初审案件 → 选择分流去向（法律援助/人民调解/司法所转介/热线解答/商业律师）→ 提交后自动生成服务单与特殊规则协同任务
3. **指派与接案**：`staff01` 指派律师（请假律师有标注）→ `lawyer01` 在案件池看到案件事实、关键期限、证据完整度、冲突主体 → 提交利益冲突核查 → 接受案件
4. **服务单协同**：材料补正（居民收到待办）、上门协助（志愿者）、联动单位（司法所）、重新指派（律师请假自动触发）
5. **结案归档**：案件须完成规定服务阶段（法援案件须律师接案进入「服务进行中」；其他类型须已分流/转介），且咨询意见、材料补正记录、转介去向、律师工时四项归档资料齐全方可结案，否则返回 4xx 且状态不变；结案后 `resident01` 评价满意度 → `staff01` 登记回访
6. **统计评估**：`staff01`/`judicial01`/`admin` 查看统计分析（类型/分流/来源分布、特殊案件、律师工时与满意度）

## 权限与留痕规则

- **结案**：仅社区工作人员或承办律师；未初审/未进入服务阶段的案件不可结案；归档四项必填缺一不可
- **协同任务**：任务状态仅「任务负责人、对应角色成员（角色任务）、管理员」可变更，他人（如居民操作司法所/律师任务）返回 403；任务完成时记录真实执行人（completedBy）并写入案件时间线

## 特殊规则说明

| 情形 | 保密 | 优先级 | 自动协同任务 |
| --- | --- | --- | --- |
| 家庭暴力风险 | 严格保密（未承办人员看到脱敏身份） | 紧急 | 联动妇联/公安/司法所（司法所） |
| 欠薪群体 | 普通 | ≥高 | 联动劳动监察部门（社区） |
| 老人赡养 / 纸质补录 | 普通 | ≥高 | 志愿者上门协助 |
| 涉未成年人 / 未成年人权益 | 保密 | ≥高 | 通知监护人 + 联动未保中心 |
| 诉讼时效 ≤30 天 | — | 紧急 | 期限盯办任务 + 红色警示 |
| 对方已起诉 | — | ≥高 | 详情页橙色警示 |
| 律师临时请假 | — | — | 名下在办案件自动生成重新指派任务 |

## 期限风险提醒

| 要素 | 规则 |
| --- | --- |
| 期限推算 | 明确诉讼时效 > 时效/开庭类关键节点 > 事件日期 + 法定时效（劳动仲裁 1 年、租赁诉讼 3 年） |
| 风险分级 | 逾期=EXPIRED；≤30 天=HIGH；≤90 天=MEDIUM；其余=LOW；期限临近且无已核验证据自动升一级；已结案/已转介解除 |
| 首页预警 | 中/高/逾期案件置顶工作人员案件列表页，按剩余天数排序，避免被普通咨询淹没 |
| 高风险处置 | 工作人员可一键生成标准材料清单（通知居民补交）、优先指派律师、登记居民是否愿意立即启动程序 |
| 提醒留痕 | 每次期限提醒记录方式/内容/距期限天数，自动评估及时性（及时/临近/逾期），汇总进统计分析用于复盘 |

## 验证方式说明

本项目以「`docker compose up -d` 健康 + 关键业务流可走通」为验证标准：

1. `docker compose up -d --build` 后 `docker compose ps` 三个服务全部 healthy/running
2. `docker compose port web 3000` 取得宿主端口，浏览器打开登录页
3. 按上方「关键业务流程」用演示账号走通：提交 → 初审分流 → 指派 → 冲突核查 → 接案 → 补材料 → 结案 → 评价 → 统计
4. API 健康检查：`curl http://localhost:<端口>/api/health` 返回 `{"ok":true,...}`
